## 1. 需求来源与判定规则

按以下顺序判定是否属于本项目需求：

1. 用户在本次项目对话中明确提出的要求。
2. 已经确认并执行的 `docs/rebuild-execution-plan.md`。
3. 前后端当前分支中已经实现、且与前两项一致的功能。

没有出现在上述来源中的功能不进入本轮范围。技术建议只能作为建议单独提出，不能直接进入开发清单。

状态定义：

- **已完成**：已有代码、数据或明确执行证据。
- **代码完成，待服务器验收**：仓库实现已经存在，但生产环境还没有可复核的验收结果。
- **待执行**：属于已确认需求，但仍需要服务器操作或配置。
- **已延期**：用户明确要求放到后续执行，本轮不作为阻塞项。

## 3. 2026-10-13 生产使用反馈

用户在实际管理和发布过程中确认了三个缺口：公开分类/标签链接进入 404、分类/标签管理过于简单、文章封面上传请求访问了浏览器不可达的 `host.docker.internal:9000`。这些项目均属于原有分类、标签和媒体功能范围，不是新增业务需求。

对应代码已修复，但在新 Web/API 镜像部署到服务器前仍不能标记为生产验收完成。

## 4. 明确不纳入本轮的内容

以下内容没有被用户要求，或已被用户明确延期，因此不进入本轮开发：

- 自助把普通账号提升为管理员的功能。
- 新增注册、管理或内容模块。
- 再次重做已经完成的前端视觉。
- 旧媒体对象迁移和最终切流。
- HTTPS/TLS 配置。
- 真实 SMTP 配置和邮箱注册验收。

## 5. 当前唯一的功能与部署闭环

1. 发布并部署本次 Web/API 修复镜像。
2. 确认首页展示的分类与标签来自服务器数据库，点击后不再进入 404。
3. 使用现有管理员账号创建和编辑分类、标签。
4. 清空服务器 `.env` 中的 `MEDIA_PUBLIC_URL` 与 `MEDIA_UPLOAD_PUBLIC_URL`，确认封面上传使用站点同源 `/media/`。
5. 使用现有管理员账号完成文章发布和公开阅读验收。

详细执行顺序和验收标准见 `docs/remaining-work-plan.md`。
